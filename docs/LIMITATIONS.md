# Limitations

What this project does not do, or has not been shown to do. Numbers below were measured on the datasets named; none is a guarantee for your media.

## Detection quality

- **Overall accuracy is unmeasured.** No labelled AI-versus-real dataset ships; thresholds were tuned on synthetic fixtures. Use `services.calibration_cli` on your own labelled media to get real numbers ([how](USER_GUIDE.md#measure-real-accuracy)).
- **Heuristics, not a classifier.** Apart from the face check and an optional image backbone you train yourself, every AI-versus-real decision is hand-written threshold logic over pixel, spectral, temporal and metadata signals.
- **"PRNU" is a median-filter noise residual**, not a camera fingerprint.
- **Faces are found with YuNet**, a published CNN detector bundled in `core/models/`. A manual review of 36 photographs looked right (including one 33 px background face), but recall and precision are not measured. The facial *deepfake-risk* score on top of it is a texture heuristic.
- **The face-authenticity model is only as general as its training set.** It was fine-tuned from ImageNet-1K ResNet-18 weights on one Kaggle dataset ("Human Faces Dataset": 5,000 real and 4,630 AI-generated pictures, 9,630 faces: 7,753 to train, 1,877 held out) and scores 100 % on that dataset's held-out faces, which says the dataset is easy, not that the model is. The split keeps near-identical pictures (difference-hash distance of 2 bits or less) on the same side; the AI class holds such groups (the largest has 560 pictures), which a hash-of-the-bytes split would have spread across both sides. Behaviour on faces from other generators (Midjourney, Flux, face swaps, beautify filters) is unmeasured. On 44 faces from 36 real phone photographs the previous version called none AI-like; that check was not repeated for this retrained version and covers false alarms only. The licence of the dataset could not be confirmed and the ImageNet starting weights carry non-commercial terms (see THIRD_PARTY_LICENSES.md).
- **Recognition is zero-shot.** Place, species and vehicle type are the best match inside a fixed vocabulary, so they always return something; results below 30 % are shown as "not sure". Rare species and specific vehicle models are weak spots.
- **Expression recognition is indicative.** The model reaches about 88 % on a posed-face benchmark; real photographs (stern group poses, sunglasses, side views) are harder, and "disgust" is over-reported.
- **Same-person matching works within one photo set only**: nothing is stored and no names are attached. It is accurate on frontal faces and weak on small, blurred or turned faces.
- **A generator is named only when the file itself declares it** (a visible watermark, or a metadata or software claim, all unauthenticated). Spectral slope, motion variance, cutoff frequency and canvas size are shared by many generators and by ordinary cameras and codecs, so they rank candidates but never name one; without a declaration the answer is "Unknown" and no candidates are offered. A file name is never used. Attribution never changes the verdict.
- **C2PA is presence-only**; signatures and hash bindings are not verified, and a bare four-letter tag counts only next to the JUMBF box type. **EXIF is unauthenticated.**
- **A cue that could not be measured is not a calm reading.** Fewer than three frame differences, fewer than three frames for flicker, an unreadable EXIF field or an unmeasurable spectrum are reported as "not measured" (`None`) and take no part in the score.
- **A file name is not evidence.** Nothing in the verdict, the screenshot decision or the attribution reads it.
- **Blank or degenerate media get "no usable content", not a verdict**: a single flat colour, silence, all-blank video frames. Pictures and videos whose shorter side is under 64 px are rejected with the reason.
- **Learning is shallow.** Feedback nudges a few scalar weights, and only from values that were actually measured for that file; real model training is a separate, manual step. The same file (identical bytes) with the same answer is counted once, so repeating a submission cannot push the thresholds further; near-duplicates (re-saves, resizes) are still treated as different samples, and anyone who can submit feedback can still skew the thresholds with many distinct files.
- **No confidence band above "leaning".** `core/bands.py` keeps `HIGH_CONFIDENCE_ENABLED = False`: until the scores are calibrated on labelled media, no result is labelled "high confidence", however extreme the number.
- **Hard JPEG compression hides grain.** A JPEG saved below libjpeg quality 95 (or with unrecognised tables) has lost fine grain whatever made it, so noise, smoothness and spectral-slope readings are not counted towards AI for it; they may still count towards real. Images under 512 px on the short side are not scored on spectral slope. Both rules were set from synthetic re-save experiments, not a labelled corpus.
- **A block list that cannot be used switches the gate off visibly.** A missing, empty, unreadable or unparseable hash list leaves the gate `INACTIVE` with a note; it never reports `CLEAR`.
- **The out-of-distribution gate needs at least as many reference files as features** (and at least 20); with fewer it stays uncalibrated rather than flagging ordinary files.
- **Text taken from a file is escaped before display** (`ui/text.py`) and spreadsheet formulas are neutralised in CSV exports, but this is checked only by unit tests and AppTest, not by a browser-level review.
- **Open items.**
  - The signature scan for scripts and HTML (`polyglot_signatures`) is a plain byte search; a picture whose metadata legitimately contains the text `<html` is flagged, and the finding is advisory only.
  - Feedback is deduplicated by file content and label and every calibration value is clamped, but many distinct, wrongly labelled files can still move the thresholds; the Learning tab shows what changed.
  - Golden tests compare digests of whole outputs: they detect any change but do not say what is right. Accuracy on real AI media is unmeasured (see the first bullet).
  - Video frames are opened by OpenCV only from local files: a link is downloaded by the hardened fetcher first, so `cv2.VideoCapture` never receives a URL.
- **What is not covered at all** is listed in [CHECKS.md](CHECKS.md#not-covered).

## Operations

- **Platforms.** Tested on Windows locally and on Linux (Python 3.14) by CI on every push. macOS has never been run.
- **GPU.** The CUDA path exists but has never been run; the tests cover CPU behaviour.
- **Scale.** Nothing tests sustained heavy load. Analysis is CPU-bound; see [Performance](../README.md#performance) for measured times. Concurrent analyses are safe (six at once gave results identical to sequential runs) but share one set of models in one process.
- **No authentication, by design.** The app is a self-contained tool and ships with no sign-in. It listens on 127.0.0.1 by default. Per-session scratch folders keep uploads apart, but every user of one installation shares the same learned corrections, the same Learning tab (file names and notes included) and the same feedback copies; put your own access control in front of it if you serve it to other people.
- **Batches run in parallel on multi-core machines** (images and audio about 2x faster, video about 1.15x); on a dual-core machine they stay sequential.
- **Size limits** (`limits.toml`, or `OMNIFORENSICS_MAX_<IMAGE|VIDEO|AUDIO>_<FILE|BATCH>_MB`): one file up to 10 MB for an image, 100 MB for a video (and 1 hour), 10 MB for audio (and 1 hour); one batch up to 500 MB per type. Each uploader hands its per-file limit to Streamlit, so the browser refuses a bigger file at once; restart the app after changing `limits.toml`.
- **`ffmpeg` is called with only the `file` and `pipe` protocols, only the container formats the app supports (`-format_whitelist`), no terminal input and a bounded decode.** An upload that is really a playlist, concat list, HLS or DASH manifest is refused instead of being followed to other files. The program is found on `PATH` by name (on Windows the current folder is searched first), so run the app from a folder you trust.
- **Without `ffmpeg`**, WAV audio (8, 16, 24 and 32-bit PCM) is still read natively and video frames are still read through OpenCV, but compressed audio cannot be decoded and a video's audio track is skipped.

## Age and minor screening

Code: `core/perception/age.py`, `age_video.py`, `video_sampling.py`, `face_scan.py`. Evaluation tools: `python -m services.age_eval`; datasets in [AGE_DATASETS.md](AGE_DATASETS.md).

- **No model finds every child.** MiVOLO v2 (Apache-2.0) is the strongest open age model found in the October 2026 research, with a mean error of about 3.7 years on its own benchmark and 4-5 years elsewhere. A 2026 independent benchmark of 34 models found that off-the-shelf age models mislabel many minors as adults when the cut-off is exactly 18, and all are weakest under about 5 years old. The screening is therefore recall-first and sends uncertain people to a human (`review_required`).
- **The margin is a measured trade-off, chosen and reported on the same sample, so the rates are optimistic.** On 2,250 UTKFace faces with known ages, flagging "estimated age below 27, or the age-group opinion at least 50 % child or teenager" sends 99.2 % of under-18s to review (97.7 % of 16-17 year-olds) but also 87 % of 18-20, 75 % of 21-25 and 26 % of 26-35 year-olds. A plain "age < 18" rule finds only 85.6 % of minors (46.7 % of 16-17). Those faces are pre-cropped and well lit with one face per image; real photographs will do worse. UTKFace is licensed for non-commercial research only.
- **Faces and bodies must be visible.** People whose face and body are both too small, cut off or hidden come back `UNDETERMINED`. Drawings, cartoons and AI-generated people are aged by appearance, which was not validated for them.
- **Apparent age, not real age.** Make-up, filters, lighting and image quality move the estimate; the result says nothing about a person's actual age or identity.
- **Weights.** `core/models/mivolo_v2/model.safetensors` is the upstream file at revision `53393526c220e34cdd7b722b36d22b6f9e5f4241` (115 MB, Git LFS). The network code in `core/perception/mivolo_vendor/` is vendored from the MiVOLO repository (Apache-2.0, licence included).
- **Real photographs.** On 750 LAGENDA photographs (CC BY 2.0; group scenes, small faces) with the real detectors, 99.6 % of 722 annotated minors were sent to review, and all 69 minors with faces under 40 px were found. The figure is approximate: of the 3 recorded misses, two were scoring errors (the child was flagged but paired with the adult beside them; the matcher in `services/age_eval.py` has since been fixed and the run not repeated) and one was a sideways face. 36.9 % of annotated adults also went to review. MiVOLO v2 was trained on LAGENDA, so its age accuracy there is optimistic; on FairFace, which it never saw, the 0-2 and 3-9 groups were flagged 99.0 % and 99.5 % of the time. This is annotator-labelled Open Images data, not a sample of your media.
- **Small faces.** The screening uses its own recall-first face finder (lower confidence, enlarged overlapping tiles). In pasted-face tests a child's face reached review 85 % of the time at 20 px, 100 % at 28 px, 62 % at 16 px and 30 % at 14 px; below about 15 px nothing is reliable. The price: about 8 % of photographs with no people (animals) are sent to review because the finder sees a face-like pattern.
- **Rotated faces.** OpenCV applies a photograph's EXIF orientation on loading, so phone portraits are upright, but a sideways or upside-down face with no orientation tag is invisible to the upright face finder. Scanning every whole image rotated added only 1.5 points of recall (95.9 % to 97.4 % on 200 photographs) for about 1 s per photograph and a false face in 10 % of people-free photographs, so it is not done. Instead, a person detected without an upright face is searched, inside their own box only, for a face turned 90, 180 or 270 degrees; the younger age and larger child share of the two readings are kept, so a false face can only add a review. A sideways face on a person the person detector also misses is still not seen.
- **Video.** Frames are chosen adaptively: the frames after every content change (a cut, or someone entering part of the shot) plus a grid of at most one a second, up to 60 frames; a frame that looks like the last examined one reuses its result. One flagged frame sends the whole video to review (`REPEATED` when it recurs in at least two frames and a quarter of those examined, otherwise `SINGLE_FRAME`), and the result reports the longest unexamined stretch. On 15 synthetic clips (real LAGENDA children with faces of at least 150 px, spliced into sea-animal footage) a child on screen for 0.5-3 s was flagged in 13 of 13 clips, against 5 of 13 with 16 evenly spaced frames; 2 child-free controls were clear. Clips longer than about a minute exceed the 60-frame budget, so the grid thins (a 10-minute clip gets about one frame every 10 s) and shorter appearances can be missed. There is no tracking: the same child in ten frames counts as ten sightings. No real video set was measured.

## AI-versus-real verdicts on photographs

- **False "AI" on real photographs is reduced, not gone.** On 600 real colourful animal photographs from a public sea-animals dataset, the AI verdict fell from 22-49 % of each folder in a first blind test to 5-12 %; 54 of the 600 are still called AI, mostly by the CGI / digital-art route (25) and by pixel evidence (23).
- **The digital-art weight change had no measurable effect.** Old and new weight gave identical verdicts on the same 664 photographs; the earlier hue and small-image fixes did the work. The new weight is kept because a likelihood ratio cannot exceed 1 / P(finding | real) and the finding fires on 4-20 % of real photographs.
- **Two metadata and noise false positives were fixed.** (1) The generator match was a plain substring search, so the camera field `aux:ImageNumber` matched "imagen"; it is now whole-word, and ambiguous short names (gemini, flux, runway, sora, pika, luma, kling, imagen) count only in software-naming fields. (2) The "uneven local noise" (inpainting) finding fires on 6-20 % of real small photographs but on 4 % of AI faces, so it is not counted for images of 400 px or less. Held-out AI faces are unchanged (300 of 300 still AI).
- **Some real files really are AI-related.** Photographs credited "Made with Google AI" or enhanced with Topaz Photo AI are correctly reported as AI-related.
